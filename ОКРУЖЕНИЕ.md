# Окружение и воспроизведение

Архив переносит проект, звуки, исходную озвучку, две готовые версии и конфигурацию установки. Он **не переносит** операционную систему, Node/Python/Chromium/FFmpeg, папку node_modules, модели ASR, секреты или аккаунты. Для первой установки обычно нужен интернет; конкретные версии и библиотеки ОС зависят от платформы. Инструкция Docker прилагается как вариант, но в среде сборки этого архива Docker не проверялся. На Windows удобно использовать WSL2. Для серьёзного рендера нужны несколько ГБ RAM, свободное место и время; начни с `--workers 2`, при нехватке памяти — `1`.

## Установка (Linux, из корня архива)

Нужны Node.js 20+ (проверено Node 24.22.1 и Playwright 1.63.0), Python 3.10+ (сборочная среда Python 3.13.15), FFmpeg/ffprobe, Chromium и npm. В Debian/Ubuntu:

```bash
sudo apt-get update
sudo apt-get install -y chromium ffmpeg python3 python3-venv python3-pip
bash setup.sh
. .venv/bin/activate
export PW_CHROMIUM="$(command -v chromium)"
```

Если системный Chromium не работает с Playwright, установи совместимый браузер: `npx playwright install --with-deps chromium` (дополнительные системные пакеты/сеть), затем `unset PW_CHROMIUM`; Playwright найдёт собственный. Установи `pip install -r requirements-optional-asr.txt` только если нужен Whisper: при первом запуске модель может скачиваться отдельно; проверь лицензии и объём.

Альтернатива Docker (проверить на своей машине):

```bash
docker build -t chtoesli-kit .
mkdir -p output
docker run --rm -it -v "$PWD/output:/kit/output" chtoesli-kit
```

В контейнере проект расположен в `/kit`, результаты пиши в `/kit/output`; исходники вне смонтированного output будут потеряны после выхода, если их не скопировать туда. Права папки `output` должны разрешать запись контейнерному пользователю. Не встраивай ключи в образ и Dockerfile; для сети/ключа используй безопасное средство своей среды. Сборка образа в данной среде не тестировалась.

## Проверка установки

Работай из `studio/`, с активной средой Python и из корня используемого комплекта. Из корня также можно запустить `bash verify.sh`:

```bash
cd studio
node tools/shot.cjs ep_tongue_frost.html ../output/test.png 0.9
node tools/text_check.cjs ep_tongue_frost.html 0.2
```

Посмотри `output/test.png`: на нём Сосед, труба и хук. Текстовая проверка сообщает только о текстовых элементах за границей изображения, а не об их смысле или перекрытиях. Возможны предупреждения favicon 404. Команды не воспроизводят звук. Можно также извлечь отдельные кадры: `node tools/sheet.cjs ep_tongue_frost.html ../output/frames 0,0.4,0.9,1.3,2.7`.

## Полная сборка примера «Язык прилип»

```bash
cd studio
# 2 работника — консервативно, можно больше при достаточной памяти.
node tools/prender.cjs ep_tongue_frost.html ../output/tongue_silent.mp4 --workers 2
# Готовый микс уже включён; тайминг соответствует текущей v5.
ffmpeg -y -i ../output/tongue_silent.mp4 -i ../episodes/tongue_frost/audio/mix_vo.wav \
  -map 0:v:0 -map 1:a:0 -c:v copy -c:a aac -b:a 192k -movflags +faststart ../output/tongue.mp4
ffprobe -v error -show_entries stream=codec_type,width,height,r_frame_rate,nb_frames,duration -show_entries format=duration -of json ../output/tongue.mp4
cd ..
python tools/qa_video.py output/tongue.mp4 output/qa --every-frames 15
```

Не добавляй `-shortest` к последнему mux: раньше он отрезал кадры. При изменении времён или звуков микс необходимо пересобрать: `node tools/sfx_dump.cjs ep_tongue_frost.html ../episodes/tongue_frost/audio/sfx.json`; `sfx_dump` пишет новую длительность, а `mix_tongue_vo.py` ожидает старую 41.3 — вручную установить `dur` в 41.3 для этого конкретного эпизода, сохранить старые времена событий и затем `python tools/mix_tongue_vo.py`. Если изменялась карта или речь, сначала адаптировать `voice_tongue.py`, выполнить её, обновить sfx и микс, проверив связи слов с кадрами; это не универсальные скрипты и они перезаписывают данные. Используй копию и перепроверь итог. Произвольный сюжет требует собственного плана тайминга и сведения, а не подстановки в эти скрипты.

Для старого blackout см. его исходник и `docs/PROJECT.md`. В архиве доступны готовые WAV-звуки, но не все исходные Mixkit MP3 раннего blackout: `foley.py` без аргументов поэтому может не восстановить все звуки. Используй готовые WAV или получи недостающие исходники с проверкой лицензии. Старый пример также содержит синтетические звуки, не используй их в новых видео без отдельного согласия.

## Практическая проверка аудио

```bash
ffmpeg -hide_banner -i output/tongue.mp4 -af ebur128=peak=true -f null - 2> output/loudness.txt
ffmpeg -hide_banner -i output/tongue.mp4 -af silencedetect=n=-45dB:d=0.4 -f null - 2> output/silences.txt
```

Результаты — не замена прослушиванию: тишина может быть выразительной, а нежелательная пауза не обязательно абсолютна.

## Источники, лицензии, безопасность

В `studio/tools/foley.py` есть ID и названия многих исходников Mixkit, CSV источников — в папках эпизодов. Разрешения на использование голоса, фрагментов, шрифтов, логотипа и звуков должны быть проверены перед публикацией; полной лицензионной ведомости в архиве нет. Проверь наличие коммерческих прав и актуальные условия каждого поставщика. Записи голоса предназначены для демонстрации проекта; право синтезировать новые тексты не предполагается автоматически. Не загружай ключи, личные данные, `.env`, историю или сторонние секреты в ZIP. Скрипт TTS умеет читать локальный путь исторического окружения `/data/.secrets/...`; предпочтительнее безопасно заданная переменная окружения.
